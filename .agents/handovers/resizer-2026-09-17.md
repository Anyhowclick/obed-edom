## OPEN 1 — offline-write fallback rate (CHARACTERIZED 2026-09-17; hypothesis overturned)

- **ORIGINAL SYMPTOM:** 704 of 3290 offline-write specs (~21%) fell to the AppleScript fallback;
  126 of 148 slides had `missed>0` (`value_clean=True` throughout — correctness fine; the concern
  was speed + Keynote dependence). The original hypothesis was a *systematic patcher gap* — some
  spec kind the surgical writer refuses and defers — worth extending the patcher to own.
- **FINDING (the hypothesis is WRONG).** Instrumented the patcher to tag every deferred spec with a
  coarse miss reason (`feat/offline-fallback-reasons` @ `5ea2ce2`, per-spec `miss_reasons` aligned
  with `missed_specs` → `run_offline_write` `fallbackReasons`/`fallbackReasonsBySlide` histogram),
  then re-ran the full deck (2026-09-17; reproduced the benchmark exactly — 3822 applied / missed 0,
  zorderGui 0, fallback covered every spec, no unwritable). The 704 misses break down as:
  - **`text-autosize` 427 (61%)** — the writer can't refresh Keynote's autosize `naturalSize` render
    cache offline. (Initially read as fundamental; the RESEARCH below overturns that — the size need
    not be computed at all, only the box repositioned.)
  - **`masked-media` 188 (27%)** — the writer refuses a real crop rather than mis-write it. (Initially
    read as fundamental; the RESEARCH below shows the axis-aligned crop transform already exists.)
  - **`group-needs-keynote:group-residual` 83 (12%)** — residual/rotated groups need live layout.
  - **`group-child-scale` 6 (0.9%)** — the only arguably-closeable family.
  - **`unresolved` = 0** and **`*-resize-unwritable` = 0** — the two "maybe closeable" families
    (addressing/reconcile gaps, editableBezier node rescaling) contributed NOTHING. There is no
    surgical-patcher gap.
  - Worst slides confirm the mix: 123 `{text-autosize 86, masked-media 4}`, 57 `{ta 26, mm 1}`,
    70 `{ta 23, mm 1}`, 103 `{ta 19}`, 135 `{mm 17}`, card-wall 125/127 carry the group-residual +
    child-scale specs.
- **INITIAL CONCLUSION (later revised):** the first read was that ~99% of the fallback is *fundamental*
  classes the writer correctly defers, and the ~21% is not a gap to close. That framing conflated "the
  writer refuses it" with "impossible" — the RESEARCH below shows both dominant classes are recoverable.

## OPEN 1 — SECOND ADVERSARY (verify-2, 2026-09-17): both claims BYPASSED the production guards

A second independent reviewer found the experiments do not validate a shippable path, because each one
routed AROUND the exact guard the shipping code enforces. This is the authoritative status:

- **Text reposition:** every text box on the evidence deck's slide 103 has `geometry.size.height == 0.0`
  (the autosize sentinel), so the production dispatcher hard-misses ALL of them at `iwa_write.py:632`
  BEFORE `_text_fields` is ever called. The e2e's 0px-drift result came from calling `_text_fields`
  DIRECTLY (bypassing `:632`) — it validates the CHANGE's mechanic (a position-only write to an autosize
  box survives a Keynote reopen), not the shipping path. To ship, `:632` must be narrowed to miss only on
  a sentinel-AXIS *write* and pass position-only through — an unbuilt, unintegrated change.
- **Masked origin-crops:** `_is_identity_mask` (`iwa_write.py:382-389`) requires the mask be the SAME SIZE
  as the frame (no crop); every real crop (H/HV/V) is refused at `:413`, so `_masked_media_fields`'
  transform (`:416-426`) never runs in production. The maskcrop harness replicated the transform past the
  gate — so it validates that the transform, once applied, renders correctly across a reopen, not that
  production writes it. To ship, `_is_identity_mask`/`_masked_media_fields` must be relaxed to admit
  origin crops — a change the code deliberately avoided (Keynote crop redistribution is unproven offline).

- **The two linchpins came back CLEAN (this is the good news):** (1) *Seed ordering is CORRECT* — the
  soft-seed `bulk_geometry` read (`remap_keynote.py:1460` → `offline_write.py:353`) runs AFTER pass-1
  `_run_jxa` (`:1427`) and its saved-and-closed guard, on the refonted deck; the reposition math is a pure
  translation independent of `naturalSize`. (2) *Stale `naturalSize` does NOT corrupt any gated offline
  check* — a reposition-only `_text_fields` write emits ONLY `pos_x`/`pos_y` (no `natural_*`), so it adds
  no `size`↔`naturalSize` disagreement; `verify_offline_frames` excludes text; `derive_kind_index`/z-order
  key off `drawablesZOrder` order not geometry; `verify_live_frames` reads the live re-rendered payload.
  My two scariest worries are retired.

- **Remaining before any build (verify-2 + owner):** (a) build the guard-lift and test through the FULL
  `run_offline_write` path (not a direct `_text_fields` call); (b) confirm the box survives the pipeline's
  MULTIPLE reopens (preview export + pass-2 stat-finalize), not just one; (c) the evidence deck is not in a
  clean-gate state — verify-2 found 3 pre-existing GATING `text-natural-width` violations on slide 103
  (ki0/1/2, `size.width==0.0`, un-laid-out) that would set `offlineVerifyPass=False` in verify mode.
  Owner steer (2026-09-17): even the 9%-top subset is worth shipping ("9% > 0%").

- **`text-autosize` (427, 61%) — reposition, don't resize.**
  - *Don't derive the size offline* (`ta-derive`, measured on the deck): the `iwa_text_shape.py` TextKit
    + per-font linear height model is calibrated for AzoSans/ArgentCF; this deck is **Amplitude/
    AmplitudeCond-dominant → ~96% uncalibrated font**, plus wrap-boundary cliffs (~50px even on the
    calibrated font — a linear model can't fix a wrong line *count*) and condensed-font width (2.2×).
    Deriving size offline is intractable and the loose text verify (4px, x/y only) would HIDE the error.
  - *You don't need to* (`ta-seed`, the key finding): pass-1 JXA applies the target `fontSize` with
    geometry suppressed (`remap_keynote.py:1389`, `remap_keynote.js:240-242`), so **Keynote already
    re-grows every autosize box to its final `naturalSize` before the offline writer runs** — and the
    mandatory bulk seed already captures that grown size, then DISCARDS it because the miss check at
    `iwa_write.py:632` bails on the sentinel before `_text_fields` (already axis-safe) can use it. The
    offline pass only needs to REPOSITION.
  - *The win:* narrow `iwa_write.py:632` (it currently misses EVERY autosize box, even pure moves) +
    have the planner (`map_remap.ItemTransform.as_dict`) drop `h` for standalone autosize text →
    convert the **top-aligned** boxes (a majority on this left/top-aligned deck) to offline position
    writes, AND remove the entire fallback Keynote pass (the bulk-seed open was already paid — the real
    wall-time lever). Residue: middle/bottom-aligned boxes whose height changed. Open census tension:
    `ta-derive` measured 660 grow-both vs 123 grow-height boxes — bounds the anchor-safe fraction.
  - *Gating experiment — PASS (2026-09-17, real deck).* Offline-moved a top-anchored grow-height
    autosize box (slide 4, sentinel height, `naturalSize.h`=270.6) by +137/+91, then round-tripped
    through Keynote. Persisted geometry held exactly (Δ0.00; Keynote rewrote `Document.iwa` but left
    the slide member untouched → no re-anchor), and Keynote's **live** layout renders it at the
    written position (x=3532,y=180). Bonus: live height came back **351** vs stored 270.6 — Keynote
    re-grows autosize height at render and the top-left is unaffected, exactly as the top-anchor
    theory predicts. (Harness: `scratchpad/reanchor_{A,C}.py` + `reanchor_open.applescript`.)
  - *VERIFY CAVEAT (independent, 2026-09-17) — the mechanics are real but this DOES NOT establish
    class recovery.* The verifier confirmed Keynote genuinely re-laid-out (live h=351 is `obj.height()`,

    boxes, only **11 are top-anchored; 112 are `kFrameAlignMiddle`** — the harness grabbed the first box

    visible rect (rendered top-left AND Keynote-grown height), plus eyeball the PNG for clipping.
