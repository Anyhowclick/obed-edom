## 0. Summary

- **Root cause (player, not host).** Keynote's export encodes a slide Dissolve as two flattened full-slide textures: the
  incoming slide at the bottom with **no animation**, the outgoing slide on top with `opacity 1→0` (EaseInEaseOut, 1.5 s on
  P2). The CSS renderer replays exactly that. Over an opaque outgoing texture this is already an exact cross-fade; where the
  outgoing texture is transparent the incoming slide shows at full strength from the first frame (pop-in). Keynote and every
  opaque export hide this because the outgoing texture carries a full-slide black fill. The trigger is that fill's absence,
  not the transparent page (§1.3).
- **Fix.** Three count-checked, sha-pinned, in-memory replacements (D1–D3) appended to `_MM_OPACITY_REPLACEMENTS`:
  for a transition whose layer tree is exactly the Dissolve shape, the player builds the transition from a **copy** of the
  export tree in which the incoming leaf starts at opacity 0 and carries the mirror animation `0→1` (same timing, curve,
  fill — generated by the player's own keyframe code and started in the same style pass), and both leaves composite with
  `mix-blend-mode: plus-lighter` inside an `isolation: isolate` container. Result: premultiplied
  `(1−e)·P_out + e·P_in`, the View Transitions cross-fade.
- **Measured (headless Chrome 154, P2 2→3, transparent page, correctly stripped PDFs).** Patched: per-frame model residual
  ≤ 1.4 LSB (2.7 under `--disable-gpu`) over every mid-transition frame, overlap α 255 (254 software) throughout (no dip),
  incoming α mirrors outgoing α (Σ = 255 ± 1), both CSS animations share one `startTime`, `in + out = 1 ± 1e-6`,
  `in = ease-in-out(t/1.5 s) ± 1e-6`. Null (stock): incoming α = 255 from the first changed frame, residual 206. KB (mirror
  fade without `plus-lighter`): overlap α 191 at e = 0.53, as predicted. Details §8.
- **Scope.** Engages on every output (equal to stock within 1 LSB wherever stock was already right).
  Only `apple:dissolve` is in scope; the `none` cut shares a one-frame variant of the same assumption (follow-up).
- **Switch.** Recommended: the existing `mm_opacity` switch (one rollback, precedent hand-back 2a). `RUNTIME_VERSION` stays 2;
  `off` stays today's bytes.

## 2. Arithmetic (premultiplied RGBA, 0..1; e = eased progress, out-going opacity o = 1 − e)

- **Stock:** `C = o·P_out + (1 − o·α_out)·P_in`, `α = o·α_out + (1 − o·α_out)·α_in`.
  - `α_out = 1` (opaque outgoing): `C = (1−e)·P_out + e·P_in` — already the cross-fade.
  - `α_out = 0`: `C = P_in` from the first frame (the measured pop-in).
- **Two plain opposite fades (rejected):** where both are opaque, `α = 1 − e + e²` = **0.75 at e = 0.5** (the dip;
  Archibald, see §7).
- **Fix:** the container is an isolated group (starts transparent, Compositing §3.2). Incoming, opacity e, `plus-lighter` onto
  zero = `e·P_in`; outgoing, opacity 1 − e, `plus-lighter` (Compositing: `co = min(1, αs·Cs + αb·Cb)`,
  `αo = min(1, αs + αb)`) gives `G = (1−e)·P_out + e·P_in`, `α_G = (1−e)·α_out + e·α_in`. **No clamping ever**: each
  premultiplied channel ≤ its α and `(1−e)·α_out + e·α_in ≤ 1`. `G` then composites source-over onto whatever lies below
  the container, exactly as one opaque-or-not slide would. Over black, `G`'s colour = the two slides rendered on black,
  cross-faded = Keynote's look.
- **Endpoints exact:** e = 0 → incoming opacity 0 → `G = P_out`; e = 1 (`fill both`) → outgoing opacity 0 → `G = P_in`; the
  hand-off to the live slide-3 DOM is stock.
- **8-bit.** Chromium renders each blended layer to an RGBA8 premultiplied surface: `round(e·P_in)` + `round((1−e)·P_out)`
  ≤ 1 LSB off the ideal per channel; PNG readback (straight alpha) and re-premultiplication add ≤ 1. Measured max 1.4 LSB
  GPU, 2.7 LSB software compositing (§8). Gate τ = 4 LSB (§9).
- **Opaque output equivalence.** Where `α_out = 1` stock and fix compute the same value; they differ only by the extra rounding
  (≤ 1 LSB). So engaging on HDMI and on opaque exports is safe; nothing needs a mode test.

**Isolation (what the blend must not mix with).** `plus-lighter` sits on the two leaf divs; their backdrop is the container
group only (`layer<container>`: a stacking context through `-webkit-transform`, plus explicit `isolation:isolate`). The blend
therefore never touches: the page background (transparent in alpha, black in screen mode); the host hide (`#body` opacity is an
ancestor: scales the whole result; screen mode's `#obed-output-black` is a fixed sibling on top); continuity overlays, pins,
bridges and held decoders (the core inserts `<video>` into `#body` or into the **live** slide's authored layers, never into the
transition container, which holds only the two texture canvases); the GL canvas (removed with the outgoing DOM in the same task);
video layers (none inside the container). **Stacking.** DOM order and z-index are unchanged; with both leaves blended the result
is order-independent. `isolation` and `mix-blend-mode` are grouping properties, so the container's and the leaves' **used**
`transform-style` becomes `flat` (CSS Transforms 2 §7.1); the leaves have identity transforms, so no pixel moves (measured).

### 3.2 How it works

- **Faithful or unchanged.** `__obedDissolveLayer` returns the export's own object (stock path, byte-for-byte today's
  behaviour) unless the effect is a transition named `apple:dissolve` whose tree is exactly the §1.2 shape: one container
  without texture or animation; two textured leaves without sublayers; incoming with no animation, opacity 1, not hidden;
  outgoing with exactly one animation, `property:"opacity"`, `1→0`, no `keyTimes`/`path`/nested group, opacity 1, not hidden.
  Anything else, or a throw, is stock. Timing, curve, `fillMode`, `beginTime`, custom control points are **copied**, not
  checked: the mirror goes through the same `WB` code, so any timing stays symmetric.
- **Copy, never mutate.** Shallow copies along the path root → container → incoming; the outgoing leaf and all deeper objects
  are shared read-only. `UC.script.events` (read by the observation hook and the continuity runtime) is untouched, so a
  replay of the same transition (go back, advance again) sees stock data and patches again identically. The flag lives on
  the per-play `yB` instance.
- **Incoming invisible from DOM insertion.** `initialState.opacity 0` makes `addNode` write `opacity:0` on the incoming
  layer div at render; `applyCssAnimation` sets it to 1 and starts the wrapper at keyframe 0% (opacity 0) in the same task as
  the outgoing's start. This covers the render→animate gap (§1.1) and an automatic transition's `beginTime` delay, where stock
  shows the incoming at full on transparent slides.
- **One clock.** Both keyframe rules are created by `WB` and started by one `applyCssAnimation` loop in one style pass:
  measured identical `startTime` and `in + out = 1 ± 1e-6` at every rAF (§8).
- **Blend applied with the DOM.** `__obedDissolveBlend` runs after `draw` and before `removeChild` in the same task, so no
  frame shows the new DOM unblended. It applies all three styles or none (`n.every(Boolean)`); by construction `addNode`
  creates every `layer<id>` it looks up (CSS path, no `canvasId`).
- **GL transitions and builds never reach it**: D2 is inside the base-layer branch; GL names fail the name test; builds go
  through `renderEffect`.
- Strict-mode class bodies: every new name is a method, parameter, property or local; every name carries `__obed`/`obed`,
  which occurs 0 times in either stock player.

### 3.4 Alternatives rejected

- **WAAPI / CSS on the incoming DOM only** (no JSON copy): a second clock; start-time alignment with the player's CSS
  animation is not guaranteed; cleanup is ours, not the player's.
- **Plain mirrored fade without `plus-lighter`:** the 0.75 dip (KB arm, §9).
- **2D canvas `lighter` per frame / WebGL:** per-frame JS compositing of two 1920×1080 textures; far larger surface.
- **Host-side CSS (program page):** the layer ids are per-play; the incoming animation still needs the player.
- **Patch only in alpha mode:** unnecessary (§2 equivalence) and would add a second pin set per mode.

## 7. Browser support (sources)

- `mix-blend-mode: plus-lighter` shipped in **Chrome 100** (ChromeStatus feature 5677338286096384, "Desktop: Chrome 100";
  web.dev "New to the web platform in March 2022"). Spec: CSS Compositing 2, `plus-lighter` `co = min(1, αs·Cs + αb·Cb)`,
  `αo = min(1, αs + αb)`; "Everything in CSS that creates a stacking context must be considered an 'isolated' group".
  CSS Transforms 2 §7.1: `isolation: isolate` and `mix-blend-mode ≠ normal` are grouping properties (used
  `transform-style: flat`). Rationale and dip: Jake Archibald, "Cross-fading any two DOM elements is currently impossible"
  (2021), which proposed exactly this primitive.
- **OBS 32.2.2** bundles CEF `127.0.0.0`, `SCMRevision …refs/branch-heads/6533@{#2000}` (= Chromium 127) — read from
  `/Applications/OBS.app/Contents/Frameworks/Chromium Embedded Framework.framework/Resources/Info.plist`. 127 ≥ 100.
- **Headless gates:** Google Chrome 154.0.8037.59, ANGLE Metal (GPU compositing) — measured §8. Software compositing
  (`--disable-gpu`, P2 non-GL arms): §8 arm `p2-t-patch-sw`.
- CEF's off-screen shared-texture path is only covered by DX-2 (§9.2); it is the one compositor not proven headless.
