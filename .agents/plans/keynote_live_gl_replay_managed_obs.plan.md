## 2. What differs under managed OBS (and what does not)

The G2 and core bytes, the plan and the fixture are identical to headless r2, and every in-page decision (arming, stand-downs, go-to, hand-back) is the same JS. What the headless gates could not see:

1. **Alpha/compositing.** `transparentBackground` only clears DOM chrome backgrounds (`live_continuity_js.py:1595`); the key is the player canvas's own alpha. The fixture `main.js` creates `getContext("webgl")` with no attributes (`alpha:true, premultipliedAlpha:true`), clears `clearColor(0,0,0,0)` and blends mostly `blendFunc(ONE, ONE_MINUS_SRC_ALPHA)`. G2 wraps the player's own context (`live_gl_replay_js.py:1287`) and replays its calls, so its key equals the native player's except that the α 0.2947 slot-4 override makes that square translucent (as the DOM draws it). The P2 headless gates ran G2 under `transparentBackground: True` (`p2_verdict.py:520`); the composite's alpha in OBS has never been measured — **M3**. Slot 4 (788.7, 672.9, 353×313) protrudes above the movie rect (109, 795, 952×268) at y < 795, so a translucent-over-transparent region exists.
2. **The alpha instrument is not the wire.** obs-websocket `GetSourceScreenshot` accepts a scene and re-renders it into a `GS_RGBA` texrender cleared to (0,0,0,0) with `blend(ONE, ZERO)`, reads it as `QImage::Format_RGBA8888` and saves it in the requested format (obs-websocket `RequestHandler_Sources.cpp`), so a PNG carries alpha. It is an independent render of the scene, not the DeckLink output path (profile `ColorFormat NV12`, keyer conversion in the DeckLink plugin). M0 validates the instrument; wire equivalence stays a hardware-day In4 check (M7).
3. **Hidden output.** Under attach `__obedOutput.hide()` sets `#body` opacity 0 (`live_host.py:414`); the G2 canvas is the player canvas inside `#body`, so it is hidden too, while rAF/rVFC keep running (HDMI covers with a black overlay instead). No headless gate exercised hide/show while LIVE — **M4**.
4. **Cadence** at OBS's 2× source rate — **M1**; build-1 hand-back seen frame by frame on the recording — **M2**.
5. **OBS-side lifecycle.** Seeded source settings: `shutdown: False`, `restart_when_active` unset (OBS default off), one always-visible scene, so OBS never unloads or reloads the page on its own. The product cannot reload the page mid-show: `check(reset_page=…)` resets only with no loaded session (`web/live.py:172`), and start/restart/quit/device setup are refused with a session loaded (`web/live.py:163–164`). Mid-show visibility changes are hidden launch (`--minimize-to-tray`, `managed_obs.py:891`) and the operator's **Show OBS** (`engine.show()` → `app.unhide()`, `managed_obs.py:281–287`) — the second replaces rev 1's `setup_device_begin` "visible launch", a state in which the product refuses to start a Keyer session (`web/live.py:229–231`). A manual refresh in a shown OBS window is operator action, out of scope (runbook). CEF WebGL under hidden launch is covered by M1's `injected` + LIVE + glErrors 0.
6. **Media timeline.** The counter movie ends at 46 s (Q3). The g2 session reaches `slide2-after` ≈ 40 s into media time (slide 1 ≈ 13 s of play + advance + LIVE wait + 10 + 3 + 4 + 4 + 3); a slow LIVE wait would push the tail into the end-of-media still and fake repeats. The harness records the carried decoder's `currentTime` at each phase start (`VIDEOS_JS` already reads `t`) and marks a take INVALID if `slide2-after` would end past 44 s.
7. Fixed 1920×1080 viewport, scale 1: gate regions come straight from the plan's `slotRects`/`instanceRect`; the harness asserts `continuity.scale == 1`. Sleep/wake drops OBS rAF to 30 until relaunch; the runbook forbids sleep, and the harness marks a take INVALID on any Sleep/Wake event.

**Not re-run under OBS** (decision, §9): headless gate 6's full 20-reason matrix and gate 7's full go-to matrix. Every stand-down funnels through one `standDown(reason, detail)` (`live_gl_replay_js.py:872`), the reasons are decided in page JS, and the only transport-dependent part of a stand-down is what the composite shows afterwards — which M5 samples with one reason per class and one go-to. Residual risk: a reason whose trigger depends on a CEF 127 API difference (e.g. `rvfcUnavailable`) behaves differently in OBS; mitigated by the OBS hedge (rVFC present) and by fail-closed design (a stand-down restores the native player).
