## What is broken

`verify_live_frames` (`offline_write.py:540-604`) addresses the saved deck by `(kind, kindIndex)`, which is defined by `drawablesZOrder` order. The offline z-order patch rewrites that order on every patched slide, so planned indexes stop addressing the objects they were minted for. PR #142 excluded those slides, leaving Gold 2/19 (only 6 and 10) and RAISE10 0/11 — a near-vacuous oracle that still reports `liveVerifyPass: true`. The Keynote payload carries only `kind/kindIndex/x/y/w/h/text` — no archive ids — so the bridge must be built writer-side.

## (a) Bridging approach

**Option 1 — exact permutation (chosen for all kinds on all patched slides).** `run_offline_zorder` holds `objects` (pre-patch decode), `pre_order[n]`, and `orders_by_slide[n]`. Running `derive_kind_index` twice on the same slide dict — once as-is, once with `drawablesZOrder` replaced by the new order — and joining on **`(id, kind)`** yields `(kind, old_ki) → (kind, new_ki)` for every drawable, computed by the same function that defines kindIndex. *Proves:* object-for-object planned-vs-Keynote frame equality, the same bar unpatched slides meet. *Cannot prove:* that Keynote agrees, if it re-derived element order from something other than `drawablesZOrder` — the live gate is the only proof of that.

**Option 2 — multiset bar, `group` kind on stat-finalize slides only.** Pass 2's `obedDedupPick`/`obedApplyDeletes` deletes groups by live index and reports only `dedupDeleted`/`dedupMiss` tokens, so the planned→post-pass-2 group index shift is unrecoverable from the run today. For `(stat slide, group)` only, compare the multiset of rounded planned `(x,y,w,h)` against the reported multiset, greedily matched within `LIVE_VERIFY_TOL`. Diag §2 measured 26/29 slide/kind buckets set-equal, so this is non-vacuous. *Cannot prove:* assignment — two same-kind objects swapped between two planned frames pass. Label it distinctly.

**Option 3 — restore order, read, re-patch — rejected.** Two extra zip rewrites and a second Keynote open of a final deck, to buy what option 1 computes for free.

**Optional piece 3 (closes the last bucket).** Make `obedApplyDeletes` append `dedupDel(s=N,i=M)` to the existing `report` global (`keynote.py:815-833`; add `report` to its globals), parse them, and bridge group indices by subtracting deletions below — then `group` on stat slides also takes the exact bar and option 2 disappears. Out of scope for pieces 1-2.
