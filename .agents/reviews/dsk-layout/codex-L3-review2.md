1. **MAJOR — Character windows are calculated with different typography from what is emitted.**  
   [dsk_plan.py:1042](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_plan.py:1042), [dsk_assemble.py:478](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:478), [dsk_assemble.py:1706](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:1706)  
   `wrap_line_spans` wraps the whole box at one font/45pt, while `_windowed_run_ranges` subsequently emits scaled mixed runs—e.g. 54.64pt highlights. Therefore a predicted three-line part can rewrap to four lines in Keynote. Unresolved run sizes are worse: `_windowed_run_ranges` silently skips them and chooses its scalar fallback from any resolved run, even outside the window. On current GW49 both parts are flattened to 25pt from the later 100pt run, violating the 45pt slot authority and existing gap policy.  
   **Fix:** implement run-aware line spans using the exact emitted fonts/sizes. Return an `unresolved` result for gaps; under `warn`, refuse, and under `shrink`, explicitly flatten to the 45pt lead size. Never derive a window’s fallback from a non-intersecting run.

2. **MAJOR — Autosize split parts are neither positioned nor verified safely after deletion.**  
   [dsk_assemble.py:1723](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:1723), [dsk_assemble.py:2635](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:2635), [dsk_assemble.py:3745](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:3745), [dsk_assemble.py:3938](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:3938)  
   Every part is assigned the full slot rect. For autosize boxes the emitter omits height, deletes characters, then writes `position` at the slot’s top. Keynote recalculates a shorter height, so one- and two-line tail parts are top-aligned rather than bottom-aligned. More importantly, Keynote may wrap differently and overflow, while all split slides are excluded from both offline measurement and refit. Their `OVERFLOW` record does not cause a top-level split-text refusal.  
   **Fix:** calculate a per-window content-height rect and bottom-align it, then offline-measure every output ordinal. Support per-part refit keys, or refuse when any saved part lies outside the slot. Do not blanket-skip `plan.splits`.

3. **MAJOR — A build on the split source box makes character-window splitting unusable.**  
   [dsk_assemble.py:2831](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:2831), [dsk_assemble.py:3528](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:3528)  
   Duplicating the slide duplicates the same long-box build onto every part. `_merge_split_part_builds` then treats that box as each part’s unique long item and sums all copies against the single source build, producing a surplus. If size/delete operations destroy the character build, it instead produces an unexplained missing build. No test covers character-window splitting of a built box.  
   **Fix:** define the build policy before emitting. If the build cannot be safely rewritten/distributed, refuse during planning with the box/build named. Otherwise carry explicit cloned-build semantics and verify them separately from the distinct-box split invariant.

4. **MAJOR — Badge geometry is not actually slot-authoritative, and the verifier hides the error.**  
   [dsk_assemble.py:1502](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:1502), [dsk_assemble.py:1603](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:1603), [dsk_assemble.py:2302](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:2302), [dsk_assemble.py:2477](/Users/anyhowclick/Desktop/work/obed-edom/.claude/worktrees/dsk-gen/src/obed_edom/dsk_assemble.py:2477)  
   The badge is initially set to the measured slot, but `_short_row_rects` immediately recomputes its y from the verse’s content top. For a full Standard slot this gives `774.3`, not the required `785.8`; other verse heights produce other y values. The verifier compares only x/width/height, deliberately allowing this drift. Group-child shape badges also receive a planned 40pt entry, but `_group_stacked_child_lines` applies text size only when `child["kind"] == "text"`, so their badge typography is not authoritative either.  
   **Fix:** remove the selected slot badge from generic short-row reflow, emit the exact slot rect, write its `object text` size even when represented as a text-bearing shape, and verify x/y/width/height.
