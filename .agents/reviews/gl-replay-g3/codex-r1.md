- **G34-01 — MAJOR — CLOSED CLASS**  
  **Evidence:** Guard G only protects `tryRemount` after its footprint logic ([live_continuity_js.py:1363](src/obed_edom/live_continuity_js.py:1363), [live_continuity_js.py:1450](src/obed_edom/live_continuity_js.py:1450)). `bindFacade` independently replaces an attached stub with the carried decoder and calls `play()` without checking the released-zone placement rule ([live_continuity_js.py:1530](src/obed_edom/live_continuity_js.py:1530)). The test detaches the stub before firing callbacks, so the observer’s attached-stub branch is never exercised ([test_live_continuity_js.py:3291](tests/test_live_continuity_js.py:3291)).  
  **Failure scenario:** During the 2→3 transition at `#5`, the carried decoder is detached and pooled. The player creates a fresh stub, which binds as its facade and is inserted under `#body` or another top-z parent. The facade observer moves the real decoder there and plays it, bypassing Guard G and painting over the transition. A detached facade can also reach `remount-footprint-rect` before the existing guard.  
  **Exact fix:** “For a facade whose `real === carriedMemo` while `zone === 'released'`, copy the memo’s sticky `__obedRect` before remounting. In `bindFacade`’s observer, permit the swap only when `stub.parentNode` is the parent of `findMovieCanvas(real.__obedRect, real)`; otherwise remove the media-less stub, emit `glreplay-hold {via:'stage'}`, and leave the real decoder where it is. Add an insertion-record test that fires the observer while the stub remains attached to `bodyEl`, and assert zero `dom-swap`, `remount-done`, and `remount-footprint-rect` events for both IDs.”

- **G34-03 — MINOR — EDGE CASE**  
  **Evidence:** Selection accepts any finite stored `__obedAuthoredRect` ([live_continuity_js.py:588](src/obed_edom/live_continuity_js.py:588)), but captures are not stamped with their scene ([live_continuity_js.py:759](src/obed_edom/live_continuity_js.py:759), [live_continuity_js.py:1584](src/obed_edom/live_continuity_js.py:1584)). Same-asset reassignment preserves the old rectangle because `reidentify` returns immediately ([live_continuity_js.py:443](src/obed_edom/live_continuity_js.py:443)).  
  **Failure scenario:** A decoder was measured at the target geometry on an earlier scene, is later reused at the sibling geometry, and is detached during a fast show→advance before the 200 ms capture. Its stale target-shaped rectangle makes it the unique match, so G2 uploads the wrong instance instead of receiving `unmeasured`.  
  **Exact fix:** “Whenever `__obedAuthoredRect` is written, also stamp `__obedAuthoredRectScene = currentHashNum()`. In `glCarried`, treat a candidate as measured only when that stamp equals `GL.atScene - 1`. Clear both fields when `reidentify` changes assets. Add a test with an earlier-scene target-shaped capture followed by an uncaptured sibling-position detach; `carried()` must return `unmeasured`.”

- **G34-04 — MINOR — CLOSED CLASS**  
  **Evidence:** `posterOf` marks a snapshot complete solely from framebuffer completeness; it neither verifies that `readPixels` succeeded nor restores/deletes its temporary framebuffer in `finally` ([live_gl_replay_js.py:363](src/obed_edom/live_gl_replay_js.py:363)). `restorePoster` likewise lacks `finally` restoration for texture binding and unpack flags ([live_gl_replay_js.py:384](src/obed_edom/live_gl_replay_js.py:384)). The fake GL deliberately throws only for drawing-buffer reads, hiding bound-FBO failures ([test_live_gl_replay_js.py:768](tests/test_live_gl_replay_js.py:768)).  
  **Failure scenario:** A framebuffer-complete `readPixels` reports a GL error and leaves the zero-initialized array untouched; the snapshot is accepted and a later stand-down writes zeros over the poster. If the read throws, the temporary FBO can remain bound. On WebGL2, using `FRAMEBUFFER` also collapses distinct read/draw bindings into the saved draw binding. A restore upload that throws can leave the poster texture bound with `flipY` and premultiplication disabled.  
  **Exact fix:** “Make `posterOf` exception-safe: preserve WebGL2 read and draw framebuffer bindings separately, restore them and delete the temporary FBO in independently guarded `finally` cleanup, and set `complete` only after `readPixels` returns, the context is live, and `getError() === NO_ERROR`. Make `restorePoster` restore texture binding and both unpack flags in `finally` and return success. Add fake-GL modes for a bound-FBO throw, a silent GL error, distinct WebGL2 read/draw bindings, and a restore-upload throw; assert no zero upload and exact state restoration.”

- **G34-05 — MINOR — EDGE CASE**  
  **Evidence:** Every player `clear` can upload the video before the frame is proved delimited ([live_gl_replay_js.py:414](src/obed_edom/live_gl_replay_js.py:414)). At settle, `settledSegment()` may return `null` ([live_gl_replay_js.py:1046](src/obed_edom/live_gl_replay_js.py:1046)); stand-down then restores the texture but performs no repaint because `state.frame` remains null ([live_gl_replay_js.py:861](src/obed_edom/live_gl_replay_js.py:861)).  
  **Failure scenario:** An updated or anomalous player issues `clear` without an immediately preceding `clearColor`, so no current or retained segment is valid. G2 has already replaced the poster texture with video. At settle it retires with `frameNotDelimited`, but the idle canvas retains the last movie frame until the operator advances—still not exact retire semantics.  
  **Exact fix:** “Before the first and every subsequent `perClearUpload`, require the current segment prefix to be exactly `clearColor, clear`; if it is not, invoke the existing `frameNotDelimited` stand-down before snapshotting or uploading. Keep ARM-POST’s stronger non-empty-frame validation. Add a fake-player test whose first clear lacks `clearColor`, asserting zero video uploads and poster-equivalent final pixels.”
