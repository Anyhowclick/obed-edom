## What this means for the plan

1. **Arm A and arm B are the same box type (U4 closed).** Every one of the 102 post-fallback
   grow-height boxes still has stored h == 0 and flags == 1 (width fixed, height not fixed). The
   fallback's `height:spec.h` write (`remap_keynote.py:578-588`) did not turn any grow-height box into a
   fixed-height one; Keynote kept the sentinel. Offline B (h stays 0) matches A's stored type.
2. **Width-fixed bit is set on every h == 0 box** (102/102 CG, 123/123 wall; height-fixed never set).
   So b_h (plan m1(2)) is always the width-fixed branch — no flags==0 centre-anchored class exists here.
3. **None vertical alignment does not occur** (0 on either deck). The refusal "None-per-rule" test is
   defensive only.
4. **The dominant class is middle-anchored, centre-aligned** — 91/102 (wall 112/123) are
   kFrameAlignMiddle + TATvalue2 (the "CHC …" map labels on 96/103). Only 11 are kFrameAlignTop
   (5 right, 4 left, 2 centre). If the effective anchor matches the style (m1(1)), the v1 top-only
   write converts at most ~11 boxes and the plan's KILL (effective-top < ~20 of 88) fires; the real
   lever is `v2-middle`, and single-line labels (nh 43 = one line) may make the middle-anchor h_new
   problem tractable. Slides 103 and 96 cannot leave the fallback under v1 (only their "Not Actual
   Names" box is top-anchored).
5. All grow-height boxes are unrotated and `bezierPathSource` — the rotated/unwritable refusals and
   the scalar-source unknown (U6) have no population in this deck.
6. 14 boxes have nw > 0, nh == 0 after the fallback (half-filled cache the plan's impl-gate says "does
   not occur today") — it does, one per slide on 15, 23, 80, 109, 112-113, 136-143. K5 must handle it.
